# TypoFixr 1.3.7

This release makes in-place corrections more reliable while retaining TypoFixr’s existing app identity, settings, history, API-key setup, and public download channel.

## Improvements

- Fix clipped checking and success captions. The HUD uses a measured width, wraps longer messages, stays visible over the active app, and does not take keyboard focus.
- Show “Checking text…” / “Keep your selection in place.” and “Fixed” / “Press ⌘Z to undo.” Give longer errors more time to read.
- Make recent-history rows visibly interactive. Open the full original and corrected text, copy a correction, or send feedback.
- Confirm before clearing all local history and usage counts. Keep long menu content scrollable, with clear Accessibility and API-key setup actions.
- Improve shortcut recording hints, API-key format guidance, onboarding wrapping, and Settings sizing. Show the build number in About.
- Fix the invisible permission icon and provide a visible fallback for every menu-bar state.
- Resume setup at the missing Accessibility or API-key step after an update, without resetting saved preferences or requiring a saved key to be entered again.
- Recheck Accessibility when opening the menu or pressing the shortcut, clear stale permission errors when access is restored, and open the settings panel reliably for permission recovery.
- Compare the copied selection again before replacing it; stop if the destination changes or the user interacts during the request.
- Preserve clipboard items and their available representations, including rich text, images, and file URLs. Do not restore over a newer copy.
- Keep Copy/Paste compatibility in editors that do not expose Accessibility selection metadata. Selected text, paragraph fallback, and line fallback remain supported.
- Prevent overlapping corrections and correctly release processing state on failure or cancellation.
- Reject incomplete model responses, including all `finish_reason: length` responses. Preserve user-authored angle brackets and emoji joiners and reduce false refusals for corrected apology text.
- Scope Keychain mutations to exact service/account pairs. Preserve legacy upgrades by moving only known empty-service entries, without reading or deleting other apps’ credentials.
- Isolate tests from real history, settings, Keychain entries, and app startup services. Preserve onboarding and shortcuts during deployment.
- Separate HTTP transport, prompt policy, chunking, and output validation for focused testing.

## Compatibility and validation

Requires macOS 13 or later, Accessibility permission, an internet connection, and a Groq API key. The installer supports Apple silicon and Intel Macs and keeps the `com.typofixr.app` identity and existing storage locations.

250 automated tests pass in both Swift Package Manager and the Xcode app test host. The unchanged clipboard implementation also passed four live keyboard-driven checks in separate native and WebKit test editors, covering selected text and paragraph fallback with Accessibility selection data unavailable. These fixture checks do not establish end-to-end compatibility with every app, including Codex.

Light and dark UI previews were reviewed for HUD states, empty/history/permission menus, correction details, Settings tabs, and onboarding. Layout tests cover short and wrapping HUD messages, reused window sizing, nonactivating panel behavior, and menu height limits.

## Installer

This release is version 1.3.7, build 4. If you installed an earlier draft, quit TypoFixr and replace the copy in the same Applications folder. Developer ID and development builds use different signing identities; if Accessibility remains blocked despite an enabled toggle, remove the old entry, add the exact installed app, enable it, and reopen it.

The app and DMG are signed with Developer ID, accepted by Apple’s notarization service, stapled, and accepted by Gatekeeper. The mounted installer was checked for the expected app identity, version, architectures, and signed executable. The asset name remains `TypoFixr.dmg` so existing download links continue to work. A SHA-256 checksum is provided alongside it.
